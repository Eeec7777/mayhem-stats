# 原始對局資料保存

2026-10-11 檢查採集程式與本機資料庫。檢查當下有 602 場對局，其中 Mayhem 599 場、5990 名參賽者；賽後統計只有 90 場／900 名玩家，時間軸原本只有 33 場（全模式）。

## 原本有哪些缺口

| 來源 | 原本的保存方式與缺口 | 現在的方式 |
|---|---|---|
| 對局明細 `/lol-match-history/v1/games/{gameId}` | `matches.raw_json` 已保存完整 JSON。部分欄位沒有獨立欄位，並非沒抓到 | 保留既有原文，另存每個觀測到的不同版本；最近一小時的已知對局仍重讀明細／時間軸，避免只保存剛結束時的版本 |
| 賽後 `/lol-end-of-game/v1/eog-stats-block` | 每場只有一份；僅依欄位數決定覆蓋，同樣欄位但數值更新會被忽略 | 所有不同版本皆保存；查詢表選完整度最高、同完整度最新的一份 |
| 賽後 `/lol-end-of-game/v1/gameclient-eog-stats-block` | 沒有採集。已在本機 LCU `/help` 確認存在 GET 與事件介面 | 賽後階段及收到事件時一併保存完整 JSON；實際內容需下一場賽後確認 |
| 時間軸 `/lol-match-history/v1/game-timelines/{gameId}` | 保留壓縮原文，但不回補開始採集前的舊場；同一行程失敗三次就停止嘗試 | 回補所有已存對局，保存不完整／後續完整版本；持久化退避重試 |
| 選角 `/lol-champ-select/v1/session` | 精簡過程加最後一份完整 JSON；早期沒有 gameId 的回應丟棄 | 每次觀測到的不同完整回應皆保存，含 timer、actions、未知欄位及早期回應 |
| 即時 `/liveclientdata/allgamedata` | 計算機按需取得後只保留整理結果，沒有持續入庫 | 對局中週期保存完整 JSON：事件、玩家、裝備、即時面板、遊戲狀態等來源提供的內容 |
| 英雄／裝備／增幅／符文／召喚師技能資源 | 只保留選定欄位；更新時覆蓋，說明、技能與其他原始內容沒有存檔 | 保存完整資源 JSON、所有英雄詳細檔、LCU `/help` 與遊戲版本；資源以客戶端版本分組 |
| 戰績清單、目前召喚師、gameflow 階段／session | 清單只取 `games.games`；其他多數僅使用、未保存 | 採集器在解析／篩選前保存完整成功 JSON 回應 |

歷史明細有 64 個 stats 鍵沒有獨立拆入玩家欄位，仍在原始 JSON：例如拆塔傷害 `damageDealtToTurrets`、全目標物理／魔法／真實傷害、首塔／首兵營助攻、符文及變數、視野細項、額外 playerScore、投降與違規旗標。部分已由 Cube 直接讀取 JSON；「沒有獨立欄位」不等於「不能查詢」。每次執行清冊工具可取得實際完整鍵名。

那 90 場賽後原文中已包含技能／召喚師技能施放次數、建築／拆塔傷害、治療／護盾隊友、死亡時間、拆塔參與和 ping 次數等欄位；多數尚未拆成查詢欄位。其餘歷史場次沒有當時的賽後快照。

本次實際回補 569 場時間軸，全部成功。回補後全模式 602／602 場、Mayhem 599／599 場都有時間軸，待重試佇列為 0。賽後快照仍為 90 場；Mayhem 其餘 509 場不能由目前這兩個賽後端點補取。

## 存檔與重試

`raw_payloads` 保存來源、端點、GET 參數、對局／擷取 session、首次與最後觀測時間、內容雜湊、原文大小和 zlib 壓縮 JSON。JSON 的全部欄位、巢狀結構、數值、陣列順序與 null 都保留；物件鍵的排列、空白等文字格式會標準化。相同內容去重，不同內容不覆蓋。HTTP headers 與 lockfile 認證資訊不進存檔。

LCU WebSocket 僅訂閱 gameflow 階段／session、選角 session、兩種賽後統計共五個端點的 JSON 事件。`source='lcu-event'` 保留完整事件封套（`uri`、`eventType`、`data` 與新增欄位），含 Update／Delete；適用的選角與賽後資料也會更新既有查詢表。階段事件會喚醒 GET 擷取，不必等閒置的 30 秒輪詢。斷線後重新讀取 lockfile、連線及訂閱；GET 輪詢持續作為補漏。採集器狀態的 `eventConnected` 可確認事件連線。

`origin='recovered'` 是由既有 `matches.raw_json`、`eog_snapshots.raw_json`、`match_timelines.raw_gz`、`champ_select_sessions.raw_last` 搬入的原文；保留其原本保存時間。既有精簡選角過程仍留在原表，無法憑精簡資料重建當時完整回應。

`capture_health` 記錄各來源最後成功／失敗時間、累計失敗次數、錯誤種類與 HTTP 狀態，不存錯誤本文。404 通常代表尚未準備好或已離開該階段，仍可查核；其他擷取失敗也會出現在採集器狀態的 `lastCaptureError`。

`timeline_fetch_attempts` 記錄每場嘗試次數與下次重試時間。失敗後從 5 分鐘退避，最多間隔 24 小時，持續重試；成功會清除待重試紀錄。每輪戰績同步補抓 10 場，較新的場次優先，退避中的場次不會卡住其他對局。

短暫資料使用獨立的非同步輪詢工作：選角／排隊約每 2 秒，大廳／對局中／賽後約每 5 秒，其他階段約每 30 秒。間隔另加 API 與入庫耗時。大量同步、資源下載與衍生表重建不再暫停這項輪詢。手動同步與背景同步使用鎖避免重疊。

賽後數值在相同玩家列數下更新時也會增加 `eog_revision`，使衍生計分表於下一次同步重建。

## 清冊與回補指令

預設唯讀，摘要／完整清冊都不輸出玩家身分，對局及玩家端點會依路由分組：

```powershell
uv run python capture_audit.py
uv run python capture_audit.py --json
```

透過本機 LCU 回補目前到重試時間的全部缺漏時間軸：

```powershell
uv run python capture_audit.py --backfill-timelines --limit 0
```

`--limit` 預設 50；0 表示不限場數。回補會先建立新表、搬入既有原文；不會移除原表。程式會每 25 場顯示成功／失敗數。

原始 JSON 含玩家資料，只存本機已忽略的 `mayhem.db`，沒有新增對外原文 API。沒有設定原文過期刪除，會隨場次及快照增加占用空間。

## 能保存的範圍

這是「完整保存 API 實際回傳且輪詢取得的 JSON」，並非每個遊戲動作都能觀測。輪詢之間發生又消失的狀態、採集器或客戶端關閉期間、端點逾時與未回傳的欄位，仍可能缺少。即時資料也是週期快照，不是逐次技能施放紀錄。

歷史賽後快照與完整選角／即時過程，沒有可指定舊 gameId 回補的上述端點。只有一部分資料可從既有原文或歷史時間軸補回，不能承諾恢復早已消失的內容。已檢查的歷史資料也沒有硬控／軟控分開的實際施加秒數；完整英雄技能說明可協助分類，但不能推算成當局真實控制成效。

追蹤好友的獨立對局也不會出現在這台電腦的選角、即時或賽後介面；這些來源只涵蓋本機客戶端實際經過的對局，歷史明細／時間軸則可按可用 gameId 抓取。

## 驗證

回歸測試涵蓋原文往返、未知欄位、同欄位值更新、null、不同版本去重、舊資料搬入、早期無 gameId 回應、額外賽後來源、即時資料對局連結、持久化重試、同步期間持續輪詢、事件封套／刪除事件／訂閱範圍與取消清理，以及相同列數下評分快取更新。既有計分測試的資料欄位／校準期望也更新為目前模型規格；本次沒有更改計分 SQL 或權重。
