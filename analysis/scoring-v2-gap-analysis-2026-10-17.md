## 4. 規格內部的矛盾與不可行之處

### 4.1 主軸的天花板：80 分的主分實際上拿不到

`P = 100·x/(x+E)`，而 `E = X_k·a_i/A_k` 裡的 `X_k` 包含自己。整理後 `P = 100·x / (x(1+s) + s·X_{-i})`，`s = a_i/A_k`，所以 **P 的上限是 100/(1+s)**，主職責權重越高 s 越大、上限越低。
實測：純輸出配置（r_D = 1）的 P_D 最高 66.3；r_T ≥ 0.9 的 P_T 最高 67.9；主權重 ≥ 0.4 的軸平均 P 只有 D 46.1、T 41.8、C 35.1。
結果整體分數擠在 40 ± 6，最高 61.8，規格第 7 節「主分 80、加分 20」的量尺有一大段永遠用不到；前端門檻（`PERF_GAP` 4、`PERF_SD` 19）全部要重算，MVP／ACE 會被幾分的差距決定。
這不是參數問題，是「參考量包含自己」與「主職責的參考份額大」兩件事疊在一起的結構性結果，規格第 6 節只提到「增加絕對量可能不再提高分項」，沒提到它壓低了整個量尺。

### 4.2 ε 讓低職責軸幾乎自動拿高分

低職責的人 `a = ε`，參考量只有全場的一小份，做一般的量就遠超參考。ε = 0.05 時，配置上完全不管承傷的人（w_T ≤ 0.05）P_T 平均 75.3、不管輸出的人 P_D 平均 85.8——也就是「打了普通的量」就拿到 X 的大半。
ε 調大可以壓下來（0.2 時 67／56），但同時把主職責的 P 拉高、坦克拿每隊最高分的比例從 1.64 升到 2.09。ε 同時控制兩件事（低職責加分、主職責量尺），規格把它當成單純的「防止分母為零」，實際上它是主要的形狀參數。

### 4.3 只有一人提供時，量的多寡完全不影響分數

H 在 125 場裡有 33 場只有一位提供者。這 33 人的 P_H 中位數是 90.9（= 100/1.1，ε 0.05、十人加總 0.5），**每分鐘 15 和 2,634 拿到一樣的分數**。
每隊只有一位提供者的有 111 隊。規格有承認這個限制，但它不是邊角情況：在 H 有資料的場次裡，這是最常見的形態之一。

### 4.4 coverage 重分配等於拿別的軸補保人

H 只有 17.7% 的場次可用。保人模板是 T 0.2／C 0.3／H 0.5，H 缺資料時重分配成 T 0.4／C 0.6——輔助被改成用承傷和控場打分。
實測：輔助出裝 232 人次裡 183 人次沒有 H，平均 S 29.9；有 H 的 49 人次平均 40.5。每隊最高分是輔助的比例只有應有的 0.15 倍（現行 perf 是 1.14 倍）。
規格一方面禁止把缺值當 0，一方面用重分配處理缺值；對輔助來說，重分配的效果和「把保人當 0」差不多，只是換了一個名字。這 583 場的分數全部要標「暫估」，MVP／ACE 也是。

### 4.5 功能裝只看終場、需求那一半沒有資料

- 只有終場持有，看不到購買時間（時間軸只有擊殺與拆建築事件：抽查 50 份時間軸，CHAMPION_KILL 4,961、BUILDING_KILL 338，沒有買裝事件；`lcu.py` 的註解寫有買賣裝事件，和實際資料不符），規格自己承認「終場補買刷分」無法排除。
- 需求 N_team 要逐英雄、逐增幅判定核心／附帶來源，目前 0 筆可用（2.5、2.6）。不先建好這張人工表，U 只能整欄 unknown；如果只看「有持有」就給分，就違反規格「無需求不給分」。
- 觸發相容性（受到普攻 vs 造成魔法傷害）也需要敵方 AD／AP 普攻型的判定，又是另一張表。

### 4.6 其他較小的問題

- **C 能力表與 X_k=0**：規格說能力 no 時權重設零，但目前沒有任何能力表；全部 unknown 等於沒做。整場 C 為 0 的場次是 0，所以「X_k=0 → 全員 0 分」在 C、O 不會發生；H 有 8 場會發生（但這 8 場沒有輔助出裝，實測影響 0 人）。
- **H 和功能裝去重**：規格要求「已被 H 計入的同一治療／護盾效果不重複領功能裝獎勵」——這是說保人裝的治療護盾，和重創／破盾沒有交集，實務上不會觸發，可以拿掉這條避免誤解。
- **推進加分**：O 全場平均作參考量，O = 0 的人 G 平均 0.86（來自 W），O > 0 的人 2.69；O 和勝負綁得很緊（2.2 節：敗方零值 24%、勝方 3%），所以 G 會把一點勝負帶回分數，但上限 4 分，實測 S 和勝負的相關仍比現行低（0.162 vs 0.271）。
- **跨場聚合**：v2 是本場相對分，好友比較頁的「強勢／不強勢」是跨場平均和 50 比；v2 的中心不是 50（平均 40.5），而且不同陣容下同樣的工作不同分，規格自己也說跨場平均「只能作描述」——那好友比較頁就**不能直接換成 v2**，要另外想判斷方式或保留現行 perf。
- **入庫缺值**：`db._num()` 把缺的鍵寫成 0。現在原始 JSON 全部有鍵，所以沒有實害；但要落實「缺值與零分開」，新欄位與 `_num` 的預設要改。
